# 工廠流水線實戰模擬 — 原始檔

更新：2026-11-19。成品是上一層的 `工廠流水線實戰模擬.html`（單一檔案，離線可用）。

## 重建
```
npm install three@0.128.0          # 只需一次，three.js 會被內嵌進單檔
DEMO_HTML=<demo-v2/dist/index.html> python3 build.py <輸出.html>
```
- `build.py` 讀 `parts/` 裡的檔案，依下表順序串接後寫成單一 HTML。
- 一起內嵌：three.js r128、OrbitControls、GLTFLoader、SheetJS xlsx 0.18.5（`vendor_xlsx/`，Apache-2.0）、`assets/` 的 3D 模型與部門流程頁、單一插單入口 Demo（`DEMO_HTML`）。
- 規則：載入時就會被執行的函式要用到的常數，要放在 `00_helpers.js`，不然會出現「初始化前存取」錯誤。

## 月度模型的骨架（由資料1 十二個月擬合）
| 公式 | 擬合度 |
|---|---|
| 換線次數 ＝ 36.5 ＋ 9.33 × 插單件數 | R² 0.992 |
| 等料停機 ＝ 20.7 ＋ 3.72 × 插單件數 | R² 0.964 |
| 拋料故障停機 ＝ 18.6 ＋ 2.38 × 插單件數 | R² 0.982 |
| 出貨 ＝ 150 片 × SMT 正常運轉小時 | 十二個月 149.9–150.1 |
| 準時率 ＝ 1.819 − 0.854 × 接單／出貨 − 0.0067 × 插單 × 擾動 | RMSE 0.55 個百分點 |

各功能的效果係數（例如閘門讓每張插單的換線 9.33 → 3.0 次）是【我猜的】，用「效果強度」0.50～1.00 涵蓋不確定性。逐條審核見專案文件《模擬器假設審核與評分_2026-11-19》。

## 新增一項功能
1. 在 `01_data.js` 的 `FEATURES` 加一筆（`demo:true` 才能導入；`excl` 二選一、`needs` 依附）。
2. 在 `simMonth` 加它的效果，在 `FEAT_LV`、`FEAT_ORD`、`FEAT_WHY` 給價值等級。
3. 若要影響 9/17 重播，在 `02_day.js` 的 `dayFactors` 加對應係數；若有人力影響，在 `14_labor.js` 的 `laborCalc` 加一行。

## 9/17 數字
- 導入前＝資料3：開機 47.3 h、運轉 27.3 h、稼動 58%、出貨 4,100、重測 640。
- 多停＝9/17 − 九月日平均 9.35 h ＝ 10.7 h（以 10 個無插單平日 9.1 h 為基準則為 10.9 h；文件統一用 10.7 h）。
- 導入後＝多停三項 × 功能係數（【我猜的】推算方式）。

## 匯入月份（2026-11-19 加入）
- 匯入後 `SALES`／`FLOOR`／`MONTHS` 多接一個月，`SEP` 改指向它；擬合（客訴回歸）只用前 12 個月（`N_CASE`）。
- `MDAYS` 換成匯入月份的逐日資料；九月原始逐日在 `MDAYS_SEP`。單日重播的日子代號：九月＝日，匯入月份＝1000＋日（`mdayOf`、`dLabel`、`dateOf`）。
- 罰款、客訴處理、加班費、工作天數、開機時數、人工效率、目標出貨（×1.1）改用匯入月份。
- 產生 AI 模擬月份：`月份產生器/gen_month.py --month 2026-11 [--seed N]`，說明見 `..\閱讀文件\AI模擬月份_使用說明.md`。
