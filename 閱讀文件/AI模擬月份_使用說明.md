# AI 模擬月份：產生與匯入

更新：2026-11-19

## 這是什麼
個案只給了九月一個月的逐日資料。為了測試模擬器在別的月份是否站得住，由 AI 隨機產生一個「新月份」：抽出這個月碰到的狀況，再照十二個月資料擬合出的關係，逐日算出數字。格式與資料1、資料3 相同，可以直接匯入模擬器。

**這是練習資料，不是企業資料。** 檔案、模擬器畫面都標【AI模擬】，不能當成企業實績引用。

## 怎麼匯入模擬器
1. 打開 `工廠流水線實戰模擬.html`，按左下角「資料月份」。
2. 按「選擇 Excel 檔…」，選上面的檔案。畫面會先檢查格式並列出摘要。
3. 按「用這個月重新載入」。左下角按鈕變成「10月*」，頁面上方有橘色提示條。
4. 要回到個案資料：按提示條的「回到九月」，或在「資料月份」裡按「回到九月（個案資料）」。

匯入的資料只存在這台電腦的瀏覽器裡，關掉再開仍會保留，直到按「回到九月」。

| 單日重播的下拉選單：多出新月份有插單的日子 | |

目標出貨改成「該月出貨 × 1.1」（沿用個案 +10% 的口徑），2026/10 是 115.3 千片；準時率目標仍是 90%。

## 2026/10 匯入後的結果（模擬）
- 這個月只有 24 個工作日，人工站的可用工時跟著少，**光靠系統（人工站額外時數 0）出貨最多到約 115.26 千片，差一點才到 115.3 的目標。**
- 加上人工站額外 210 人時／月（建議配置的預設）：導入 4 項（入口、閘門、齊套、料到日）、效果強度 0.70，出貨 115.4 千片、準時 90.6%、最忙站 96%。
- 結論：工作天少的月份，+10% 比九月更難做到，瓶頸還是人工站（插件）。

## 怎麼產生的（摘要；完整寫在 Excel「說明」頁）
1. **抽事件**：插單 4～18 件（平均 11）；颱風、請假潮、缺料、機台故障、跳電、品質異常、週六保養、客戶拉貨或延後，各有機率。機率是【我猜的】。
2. **月總量**：換線 ＝ 36.5 ＋ 9.33 × 插單、等料 ＝ 20.7 ＋ 3.72 × 插單、拋料故障 ＝ 18.6 ＋ 2.38 × 插單（資料1 擬合，依工作天數調整），再加隨機誤差與事件。
3. **逐日**：週一～週五全天、週六半天，週日與國定假日休；開機 ＝ 正常運轉 ＋ 三種停機（同資料3）；出貨 ＝ 150 片 × 正常運轉小時。
4. **加班**：月總量 ＝ 440 ＋ 13.4 × 停機合計（資料1：2025/10 與 2026/09 兩端），上限約 4,000 h（全廠約 100 人 × 勞基法每人每月 46 h ≈ 4,600 h，實務抓 4,000【我猜的】）。
5. **準時率**：模擬器同一條公式（1.819 − 0.854 × 接單／出貨 − 0.0067 × 插單）加小擾動；超出十二個月範圍時減半外推，最低 60%【我猜的】。
6. **金額**：罰款、客訴處理按九月個案單金額等比例推；加班費 ＝（加班 − 1,800 h）× 268 元。比例推算是【我猜的】。

## 再產生一個月
- 跟 Claude 說「再模擬一個月」即可。
- 或自己跑（要裝 Python 與 openpyxl）：
  ```
  cd 原始碼\月份產生器
  python gen_month.py --month 2026-11            （隨機種子）
  python gen_month.py --month 2026-10 --seed 735133   （重現上面那個月）
  ```
- 同一個種子一定產生同一份資料，方便重現。
- 一次產生連續很多個月：`python gen50.py 2026 12 50 輸出資料夾`（從 2026/12 起連續 50 個月，每月隨機抽種子，附 manifest.json）。

**注意**：六類壞事件機率調高後，同一個種子會產生跟之前不同的資料。2026/10、種子 735133 的 Excel 檔仍可匯入，但用這個種子重新產生會得到另一份資料。

## 隨機種子怎麼來
種子是一個整數，決定「這個月抽到什麼」的亂數起點。**同一個月份＋同一個種子 ＝ 完全一樣的資料；種子本身沒有意義。**

| 做法 | 指令 | 說明 |
|---|---|---|
| 讓程式自己抽 | `python gen_month.py --month 2026-11` | 不給 `--seed`，程式用系統亂數在 1～999999 抽一個整數 |
| 自己指定 | `python gen_month.py --month 2026-11 --seed 42` | 任何整數都可以，隨手打一個就行 |
| 找特定類型的月份 | 連續換幾個種子，看插單件數與準時率再挑 | 例：種子 2（19 件插單，很差）、種子 7（4 件插單，平靜）、種子 99（11 月） |

**在哪執行**：在你自己的電腦上，打開「命令提示字元」或 PowerShell，先進到產生器的資料夾，再下指令：
```
cd /d D:\專案\企業命題\正式模擬測試\原始碼\月份產生器
python gen_month.py --month 2026-11 --out ..\..\AI模擬月份\我的11月.xlsx
```
- Windows 上通常打 `python`，不是 `python3`。
- 要先裝好 Python，並執行過 `pip install openpyxl`。
- 沒加 `--out` 時，檔案會產生在你目前所在的資料夾；上面的 `..\..\AI模擬月份\` 是把檔案放進 `AI模擬月份` 資料夾。
- 不想自己跑，就跟 Claude 說「再模擬 11 月」，我會抽種子、產生檔案、放進 `AI模擬月份\`。

種子會寫進兩個地方：Excel「說明」頁第一行，以及預設檔名（`AI模擬月份_2026-11_種子123456.xlsx`）。要重現某個月，記下種子就好。

| 參數 | 怎麼抽 |
|---|---|
| 插單件數 | 平均 11、標準差 3.5，限制 4～18 件；客戶甲拉貨時另加 1～2 件【我猜的】 |
| 颱風 | 只有 7～10 月會抽，機率 24.5%；停班一天，隔天等料多 2～4 小時【我猜的】 |

| 客戶甲提前拉貨 | 機率 30%；接單增加 4～8 千片【我猜的】 |
| 客戶丙延後訂單 | 機率 18%，且只在沒有拉貨時才抽；接單減少 4～8 千片【我猜的】 |
| 供應商缺料 | 0 次 32.5%、1 次 45%、2 次 22.5%；每次停線 3～5 小時（再加 0～1.5 小時）【我猜的】 |
| 機台故障 | 機率 47.5%；停機 3～6 小時【我猜的】 |
| 跳電 | 機率 14.5%；多停 1.5～2.5 小時【我猜的】 |
| 品質異常 | 機率 37.5%；重測多 250～400 片【我猜的】 |
| 週六保養 | 機率 25%；4 線不開，當天運轉量剩 75%【我猜的】 |

### 二、每個插單的內容【我猜的】
- 客戶：甲 62%、乙 8%、丙追加 8%、丙換零件 22%。
- 通知方式：LINE 50%、正式單 25%、口頭 15%、電話 10%；通知時間 08:30～16:30。
- 知道的時間：正式單晚 15～35 分鐘；口頭最久 1～6 小時（沒有記錄）；LINE 晚 1～5 小時、電話晚 1～3 小時，超過下班就隔天早上才知道。
- 追加片數從 200、300、400、500、600、800 片裡挑。
- 非正式通知的甲插單，有 60% 機率讓乙或丙的訂單晚 1～2 天。

### 三、月總量用的關係式
| 項目 | 公式 | 來源 |
|---|---|---|
| 換線次數 | 36.5 + 9.33 × 插單件數 | 資料1 十二個月擬合 |
| 等料時數 | 20.7 + 3.72 × 插單件數 | 資料1 擬合 |
| 拋料故障時數 | 18.6 + 2.38 × 插單件數 | 資料1 擬合 |
| 出貨 | 150 片 × 正常運轉小時 | 資料1 十二個月都在 149.9～150.1 |
| 重測 | 130 + 30 × 換線次數 | 【我猜的】 |
| 加班 | 440 + 13.4 × 停機總時數 | 資料1 兩端（2025/10、2026/09） |
| 準時率 | 1.819 − 0.854 × 接單／出貨 − 0.0067 × 插單 | 模擬器同一條公式 |
| 客訴（遲交／品質） | 由準時率、重測率回推 | 資料1 回歸 |

三項時數依工作天數按比例縮放，各加隨機誤差（換線 ±4、等料 ±3、拋料 ±2）。

### 四、上限與假設【我猜的】
- 加班上限：3,900～4,100 小時隨機。超過的部分，每少 100 小時加班，SMT 少跑 1.5 小時。
- 準時率下限 60%；接單比例超出歷史範圍（1.114）的部分只算一半。
- 每日運轉：平日平均 33.4 小時、週六 15.2 小時；停機越多，運轉被擠掉越多。
- 人工效率基準 96%，限制在 92%～97%。
- 週六固定半天；連假前一天多加班、多出貨。
- 假日：2026/10、2026/11 用原本的表；2026/12 起依規則推定（元旦、春節除夕到初三、和平紀念日、兒童節與清明、勞動節、端午、中秋、教師節、國慶、光復節、行憲紀念日；週六遇假日補前一個上班日、週日補後一個上班日）。農曆節日日期以 lunardate 套件算出後寫死（2026～2031）。實際放假與補班日以行政院公告為準【我猜的】。

### 五、金額
全部按九月個案單金額換算，再乘 0.85～1.15 的隨機倍數【我猜的】：
- 罰款 ＝ 59 萬 ×（1 − 準時率）／（1 − 0.78）。
- 客訴處理 ＝ 25 萬 ×（遲交＋品質客訴件數）／ 14。
- 加班費 ＝（加班時數 − 1,800）× 268 元。

## 會抽到多極端？（跑 10,000 個月份統計；六類壞事件機率各加 2.5 個百分點後的版本）
4 個月份（2026/10～2027/1）各跑 2,500 個種子。

| 項目 | 最小 | 中位數 | 最大 |
|---|---|---|---|
| 插單件數 | 4 | 11 | 20 |
| 出貨（千片） | 91.5 | 108.4 | 124.1 |
| 準時率 | 60% | 77% | 97% |
| 加班（小時） | 2,050 | 3,755 | 4,115 |
| 客訴（件） | 1 | 14 | 27 |
| 罰款（萬元） | 7 | 60 | 120 |
| 工作天 | 24 | 25 | 27 |

- **很差的月份**：約 1.6% 準時率 ≤ 65%；最差是 20 件插單、準時率 60%、出貨約 92 千片、客訴 25～27 件，比九月（78%）和資料1 最差月份都慘。
- **很好的月份**：約 4.6% 準時率 ≥ 90%；最好是 4 件插單，可到 97%。
- **加班被卡住**：約 37% 的月份需要的加班超過上限，被迫少跑。
- **缺料連發**：約 22.5% 的月份抽到兩次缺料。
- 多數月份落在差到中等，因為產生器以九月（準時率 78%）為基準，不是平均水準。
- 準時率 60% 是下限，不是模型算出來的結果，真正更差的月份被截在這裡。

### 跑不出來的極端（目前沒做）
- 單月 10,000 個種子的統計裡，工作天只有 24～27 天（2026/10～2027/1，當時沒放春節）；2026/12 起的假日表有春節，工作天最少 18 天（2030/2）。連休最長是春節，沒有連休一週以上的月份。
- 颱風最多一天，沒有連續颱風。
- 機台故障最多一次、3～6 小時，沒有整條線停好幾天或大修。
- 缺料最多兩次、各約 6.5 小時以內，沒有關鍵料斷貨一週。
- 沒有客戶大砍單或流失，沒有大量離職。
- 品質事故最多多重測 400 片，沒有整批報廢或整批退貨。
- 插單最多 20 件。

**待辦（未確認要做）**：加一個「極端模式」，例如連續颱風、關鍵料斷貨一週、客戶砍單 30%、機台大修三天，或手動指定要哪一種災難，用來測模擬器撐不撐得住。

## 50 個月壓力測試（2026/12～2031/1）
目的：看模擬器與研究結論換成別的月份還站不站得住。50 個月各抽一個隨機種子產生資料，逐月匯入模擬器，各跑三種配置，記錄月度指標。

**檔案**
- 總表：`報表\50個月壓力測試\50個月_月度指標總表.xlsx`（總覽、月度指標 50 列、說明、種子與檔案）
- 逐月檔：`報表\50個月壓力測試\月度指標_逐月\`，每月一份
- 50 個月的資料檔（可匯入模擬器）：`AI模擬月份\50個月_2026-12起\`
- 跑法與腳本：`原始碼\壓力測試\`（batch50.js、eval50.js、build50.py；要有 Chrome 與 node）

**三種配置**：只靠系統（人工站額外 0 人時）、達標配置（額外 210 人時）、建議配置（額外 210 人時、最忙站 ≤95%）。判定：出貨 ≥ 該月導入前 × 1.1、準時率 ≥ 90%、最忙站 ≤100%、加班不增加。

**結果（模擬）**
| 項目 | 月數（共 50） |
|---|---|
| 導入前準時率 ≥ 90% | 4 |
| 只靠系統達標（額外 0 人時） | 19（38%） |
| 達標配置達標（額外 210 人時） | 36（72%） |
| 找得到建議配置（最忙站 ≤95%） | 23（46%） |
| 加班本來就超過 3,700 h | 21 |

- 達標的 36 個月，平均出貨 105.6 → 118.4 千片、準時率 74.7% → 91.1%、客訴 16.2 → 5.8 件、換線 147.6 → 82.1 次。月效益平均約 292 萬（按個案單價與比例推算【我猜的】）。
- 沒達標的 14 個月：出貨到不了 7、準時率到不了 4、兩者都到不了 3。其中 13 個月把額外人時加到 2,000 仍找不到，所以不是人時不夠，是 SMT 與人工站的上限。
- 比較難達標的月份：工作天 ≤21（春節、連假）達標 2／6；插單 ≤8 件的平靜月達標 4／14；導入前準時率 ≥85% 的月份達標 1／6，因為這些月份本來就接近產能上限，+10% 超出上限。
- 插單 9 件以上的月份達標率約 87～90%；導入前準時率 <70% 的差月達標 6／11。
- 月份互相獨立，年度之間的差異是抽樣誤差，不是趨勢。

**怎麼解讀**
- 這是一致性測試，不是外部驗證：產生器的換線、等料、故障、準時率關係和模擬器用的是同一組由十二個月擬合的式子，所以結果說的是「換一個月的情境組合，模型和結論是否一致」，不是「真實工廠會不會這樣」。
- 目標＝該月導入前出貨 × 1.1，是我對匯入月份定的口徑；個案原本的目標是固定 125.4 千片。
- 抽查 3 個月（2026/12、2028/09、2028/03）用模擬器自己的按鈕重跑，結果與批次一致。

## 自己的資料也能匯入
只要 Excel 有「每日紀錄」「SMT開機與停機」「產銷概況」三張工作表，欄位名稱和資料1、資料3 一樣即可。「現場概況」「損失與客戶」可以省略，省略的部分用九月比例推算（畫面會列出來）。「說明」頁沒有寫【AI模擬】的檔案，標籤會顯示「匯入」。
